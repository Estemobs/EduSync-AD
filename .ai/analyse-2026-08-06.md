## Résumé

EduSync AD est une application desktop PyQt6 de gestion du cycle de vie des comptes Active Directory pour les établissements scolaires. Le code est structuré en modules `core` (indépendants de l’UI, testés) et en modules `ui` (PyQt6). La séparation est propre, les docstrings sont en français et le projet dispose d’une suite de tests unitaires pour le cœur métier. Les derniers commits montrent une évolution active (fusion des modules, retrait du mode simulation, ajout d’un coffre-fort de mots de passe, automatisation CI). Le dépôt est bien documenté (README, guide utilisateur, protocole de test, SECURITY.md, CONTRIBUTING.md).

Cependant, plusieurs points méritent attention : incohérence entre le README et le code (mode simulation retiré mais toujours documenté), un fichier UI très volumineux (`ad_explorer_page.py`), une couverture de tests limitée aux modules `core`, et des risques de sécurité liés au repli LDAP non chiffré et à la gestion des clés du coffre-fort.

## Problèmes et bugs potentiels

- **Incohérence README / code** : le README mentionne un « mode simulation » (section « Pourquoi EduSync AD » et tableau des fonctionnalités), mais le commit `553bd4b` indique « retrait mode simulation ». Le code actuel (ex. `create_accounts_page.py`) ne semble plus contenir de mode simulation. Il faut soit réintroduire cette fonctionnalité, soit mettre à jour le README pour éviter toute confusion.
- **Repli LDAP non chiffré** : `src/edusync_ad/core/ad/connection.py` tente LDAPS puis bascule sur LDAP (port 389) avec un avertissement. Ce repli expose les identifiants et les données en clair. Il est recommandé de le rendre optionnel et de forcer LDAPS par défaut, avec une validation de certificat stricte.
- **Gestion des clés du coffre-fort** : `src/edusync_ad/core/crypto.py` et `password_vault.py` utilisent probablement une clé de chiffrement stockée localement. Il faut vérifier que la clé est protégée (permissions, chiffrement avec un mot de passe maître) et documenter la procédure de sauvegarde/restauration.
- **Fichier `ad_explorer_page.py` trop volumineux** : 73 Ko, il concentre l’arborescence, les actions, les dialogues et la logique métier. Cela rend la maintenance difficile et augmente le risque de régressions.
- **Gestion des erreurs LDAP** : les exceptions personnalisées (`ADError`, `ADAuthError`, etc.) sont définies, mais il faut s’assurer qu’elles sont systématiquement levées et capturées dans tous les modules UI (ex. `depart_page.py`, `password_reset_page.py`).
- **Mise à jour automatique** : `src/edusync_ad/core/updater.py` vérifie une somme de contrôle, mais il faut confirmer que le téléchargement se fait en HTTPS et que la somme est signée (sinon risque de falsification).
- **Sécurité du mot de passe en mémoire** : le code de connexion (`connection.py`) indique que le mot de passe n’est pas conservé au-delà de l’appel à `connect()`, mais il faut vérifier qu’il n’est pas stocké dans des variables persistantes ou des logs.

## Qualité du code et nettoyage

- **Refactorisation de `ad_explorer_page.py`** : découper en plusieurs classes (TreeView, TableView, ActionsPanel, etc.) pour améliorer la lisibilité et la testabilité.
- **Suppression du mode simulation** : si la fonctionnalité est réellement abandonnée, retirer les références dans le code et la documentation. Sinon, la réintégrer proprement.
- **Uniformisation des imports** : certains modules importent `ldap3.utils.dn.escape_rdn` directement, d’autres passent par `ldap3.utils.conv.escape_filter_chars`. Harmoniser pour éviter les duplications.
- **Documentation des fonctions** : les docstrings sont présents, mais certaines fonctions complexes (ex. dans `connection.py`) pourraient bénéficier d’exemples d’utilisation.
- **Gestion des constantes** : les constantes comme `UAC_NORMAL_ACCOUNT_ENABLED` sont définies dans `connection.py` ; il serait plus propre de les regrouper dans un module `constants.py`.
- **Nettoyage des imports** : dans `ad_explorer_page.py`, de nombreux imports sont utilisés ; vérifier qu’ils sont tous nécessaires (certains pourraient être inutilisés).

## Nouvelles fonctionnalités à envisager

- **Mode simulation réintroduit** : si le retrait est récent, il peut être utile de le réintroduire pour permettre aux administrateurs de tester les imports sans impact.
- **Export PDF des rapports d’audit** : le module `audit.py` génère des journaux, mais un export PDF (via `reportlab`) serait un plus pour la traçabilité.
- **Gestion des groupes AD** : l’explorateur permet déjà de gérer l’appartenance aux groupes, mais une fonctionnalité de création/suppression de groupes serait utile.
- **Sauvegarde/restauration de la configuration** : exporter/importer les paramètres (politique de mots de passe, OUs, etc.) pour faciliter le déploiement.
- **Mode de supervision** : permettre à un administrateur de visualiser les actions en temps réel (journal en direct) sans pouvoir modifier.

## Tests manquants

- **Tests UI (PyQt6)** : aucun test pour les modules `ui/` (ex. `main_window.py`, `login_dialog.py`, `create_accounts_page.py`). Utiliser `pytest-qt` pour tester les interactions de base (ouverture, chargement CSV, validation).
- **Tests de la connexion AD avec mocks** : les tests existants (`test_ad_connection.py`) couvrent les cas de base, mais il manque des tests pour les erreurs de certificat, les timeouts, et les opérations LDAP complexes (modification d’attributs, déplacement).
- **Tests du coffre-fort de mots de passe** : `test_password_vault.py` existe, mais il faut ajouter des tests pour la rotation de clé, la corruption de fichier, et les permissions.
- **Tests de l’explorateur AD** : `test_ad_explorer.py` couvre les fonctions de base, mais pas les interactions UI (clic droit, déplacement).
- **Tests de l’updater** : `test_updater.py` existe, mais il manque des tests pour les échecs de téléchargement, les sommes de contrôle invalides, et la gestion des fichiers temporaires.

## Dépendances et sécurité

- **Dépendances** : `PyQt6`, `ldap3`, `cryptography`, `reportlab`, `platformdirs` sont raisonnables. Les versions minimales sont correctes. `Renovate` est configuré pour les mises à jour automatiques.
- **Sécurité** :
  - Le repli LDAP en clair est un risque majeur. Il est recommandé de le désactiver par défaut et de n’autoriser que LDAPS avec validation du certificat.
  - Le coffre-fort de mots de passe : vérifier que la clé de chiffrement est stockée de manière sécurisée (ex. dans le trousseau du système) et non dans un fichier lisible.
  - La mise à jour automatique : s’assurer que la somme de contrôle est signée (ex. avec une clé publique) et que le téléchargement se fait en HTTPS.
  - Le fichier `SECURITY.md` est présent, mais il est très court (555 octets) ; il devrait détailler les procédures de signalement et les bonnes pratiques.

## Suggestions prioritaires (top 5)

1. **Mettre à jour le README** pour retirer toute mention du mode simulation (ou le réintroduire) et clarifier les fonctionnalités actuelles.
2. **Refactoriser `src/edusync_ad/ui/modules/ad_explorer_page.py`** en plusieurs fichiers pour améliorer la maintenabilité et la testabilité.
3. **Renforcer la sécurité LDAP** : forcer LDAPS par défaut, supprimer le repli automatique sur LDAP, ou le rendre optionnel avec un avertissement explicite et une validation de certificat stricte.
4. **Ajouter des tests UI avec `pytest-qt`** pour les modules principaux (connexion, création de comptes, réinitialisation de mots de passe) afin de couvrir les scénarios critiques.
5. **Auditer la gestion des clés du coffre-fort** (`crypto.py`, `password_vault.py`) et documenter la procédure de sauvegarde/restauration pour éviter la perte de données.
